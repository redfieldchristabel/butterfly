You can adopt Butterfly in two ways: add individual Flutter packages directly to your `pubspec.yaml`, or activate the `butterfly` CLI to generate models and project files.

## Prerequisites

<CardGroup cols={2}>
  <Card title="Dart & Flutter SDK" icon="code">
    The root workspace requires Dart `^3.11.0`, while `auth_management_provider_riverpod` requires **Dart `^3.12.0`** and **Flutter `>=3.44.0`**. Match your SDK to the highest package you install.
  </Card>
  <Card title="Git & SSH Access" icon="git-alt">
    Required for fetching Git-hosted packages and Mason bricks. Several internal `pubspec.yaml` files reference `git@github.com:...`, so configure GitHub SSH keys on your machine.
  </Card>
</CardGroup>

## Install the CLI

<Steps>
  <Step title="Bootstrap the workspace">
    From the root of your Butterfly checkout, resolve workspace dependencies and verify the CLI runs:

    ```bash
    flutter pub get
    cd butterfly_cli
    dart run butterfly_cli --help
    dart run butterfly_cli version
    ```
  </Step>
  <Step title="Activate globally from your local path">
    Register the `butterfly` executable on your machine from the repository root so it uses your local checkout:

    ```bash
    dart pub global activate --source path ./butterfly_cli
    butterfly --help
    ```

    <Info>
      Make sure your Dart pub-cache `bin` directory (`~/.pub-cache/bin` on Linux/macOS) is on your `PATH`. The executable name is `butterfly` (not `butterfly2`).
    </Info>
  </Step>
</Steps>

<Warning>
  Running `dart pub global activate butterfly_cli` (without `--source path`) pulls the last published version from pub.dev, which will not include local repository updates.
</Warning>

## Add Flutter libraries to your app

Every library lives under `packages/<package_name>` in the monorepo. Add only the packages your app imports.

<Tabs>
  <TabItem label="Core & Routing" value="core-deps">
    Add `core_management` and optional GoRouter support to your app's `pubspec.yaml`:

    ```yaml title="pubspec.yaml"
    dependencies:
      flutter:
        sdk: flutter
      core_management:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/core_management
      core_management_route_go_router:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/core_management_route_go_router
    ```
  </TabItem>
  <TabItem label="Auth + Riverpod + Sembast" value="auth-deps">
    Combine the base auth package with a storage adapter (like Sembast) and the Riverpod auto-sync bridge:

    ```yaml title="pubspec.yaml"
    dependencies:
      flutter:
        sdk: flutter
      auth_management:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/auth_management
      auth_management_database_sembast:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/auth_management_database_sembast
      auth_management_provider_riverpod:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/auth_management_provider_riverpod
    ```
  </TabItem>
  <TabItem label="Firebase & OAuth2" value="provider-deps">
    Add identity provider packages when authenticating against Firebase, Google, or an OAuth2 server:

    ```yaml title="pubspec.yaml"
    dependencies:
      auth_management_firebase:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/auth_management_firebase
      auth_management_oauth2:
        git:
          url: https://github.com/redfieldchristabel/butterfly.git
          ref: master
          path: packages/auth_management_oauth2
    ```
  </TabItem>
</Tabs>

After editing `pubspec.yaml`, run `flutter pub get`.

<Info>
  **Production tip:** Pin `ref:` to a tested commit SHA or tag rather than `master` so upstream changes never break reproducible builds. Note that using an `https://` URL on one dependency does not rewrite transitive `git@github.com:` SSH URLs inside the workspace packages.
</Info>

## Interactive project scaffolding (`butterfly init`)

Inside an existing Flutter project (one containing both `pubspec.yaml` and `lib/`), you can run the interactive initializer:

```bash
butterfly init
```

The wizard walks upward to locate your project root, creates `lib/models`, `lib/services`, `lib/screens`, and `lib/widgets`, and prompts you to opt into Core, Auth, and Routing scaffolds.

<AccordionGroup>
  <Accordion title="What butterfly init generates">
    - **Core enabled:** Adds `core_management` and scaffolds `CoreService` and `ThemeService`.
    - **Auth enabled:** Prompts for a user model name, adds `auth_management`, and scaffolds an auth service file. (It does not generate the user model class or pick a database package.)
    - **Routing enabled (`goRouter`):** Installs `go_router`, `build_runner`, and `go_router_builder`, then generates typed example routes. Choosing `other` skips route generation.
    - **Config file:** Interactive `butterfly init` keeps answers in memory and does **not** write `.butterfly_project.yaml` (unlike the MCP `init` tool, which does save `.butterfly_project.yaml`).
  </Accordion>
  <Accordion defaultOpen title="Known scaffolding caveats (Read before running)">
    The Mason bricks fetched from GitHub `master` currently lag behind the latest library APIs in a few places:
    1. **Auth template base class:** The brick extends `BaseAuthService`, which no longer exists in `auth_management`. Replace it with `AuthServiceRepository<T>` or `IdentityAuthRepository<I, T>`.
    2. **Theme template constructor:** The brick passes positional `super.context`, whereas `BaseThemeService` only accepts named `{Color? colorSeed}`.
    3. **Working directory quirk:** Interactive `init` changes directory into `lib/` while service generation targets relative `lib/services`, which can place generated services under `lib/lib/services`. Always inspect generated paths after running `butterfly init`.
  </Accordion>
</AccordionGroup>
