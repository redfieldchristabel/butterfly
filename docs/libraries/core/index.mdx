`core_management` provides the foundation of a Butterfly app: a singleton `BaseCoreService` that wires error handling, theming (`BaseThemeService`), and app-wide loading overlays (`BaseLoadingService`), alongside standalone mixins and extensions.

## Quickstart setup

<Info>Only `lib/main.dart` is a fixed name. Files marked **(suggested)** follow the `butterfly init` layout; rename or move them freely. Replace `my_app` in imports with the `name` from your `pubspec.yaml`.</Info>

<Steps>
  <Step title="Define your CoreService (and optional ThemeService)">
    Subclass `BaseCoreService` once for your application. Its constructor registers `BaseCoreService.instance` (`late final`), so only one instance may be created per isolate.

    ```dart title="lib/services/theme.dart (suggested)"
    import 'package:core_management/core_management.dart';
    import 'package:flutter/material.dart';

    class ThemeService extends BaseThemeService {
      ThemeService() : super(colorSeed: Colors.teal);
    }
    ```

    ```dart title="lib/services/core.dart (suggested)"
    import 'package:core_management/core_management.dart';
    import 'package:my_app/services/theme.dart';

    class CoreService extends BaseCoreService {
      @override
      final BaseThemeService themeService = ThemeService();
    }

    final coreService = CoreService();
    ```
  </Step>
  <Step title="Install error handlers and apply the theme in main.dart">
    Call `coreService.errorHandler()` during startup to attach `FlutterError.onError` and `PlatformDispatcher.instance.onError` hooks, then build your `ThemeData` with `coreService.getTheme(context)`:

    ```dart title="lib/main.dart"
    import 'package:flutter/material.dart';
    import 'package:my_app/services/core.dart';

    void main() {
      WidgetsFlutterBinding.ensureInitialized();
      coreService.errorHandler(); // first access constructs the core service
      runApp(MaterialApp(
        home: Builder(
          builder: (context) => Theme(
            data: coreService.getTheme(context),
            child: const Scaffold(body: Center(child: Text('Butterfly'))),
          ),
        ),
      ));
    }
    ```
  </Step>
</Steps>

<Warning>
  Simply constructing `CoreService()` does **not** install global error hooks—you must call `coreService.errorHandler()`. Also make sure to retain a `final` field when overriding `themeService` (the base getter constructs a fresh `DefaultThemeService` on every access).
</Warning>

## `BaseCoreService` API reference

<Property name="errorHandler()" type="void">
  Wires `FlutterError.onError` to `errorHandlerService.recordFlutterError` and `PlatformDispatcher.instance.onError` to `errorHandlerService.recordError`. The default Flutter handler calls `FlutterError.presentError`; the default platform handler returns `false` so unhandled platform errors continue through normal host reporting unless overridden.
</Property>

---

<Property name="errorHandlerService" type="BaseErrorHandlerService" optional>
  Protected getter used by `errorHandler()`. Override it with your own `BaseErrorHandlerService` subclass to forward uncaught exceptions to Crashlytics, Sentry, or your logging backend.
</Property>

---

<Property name="themeService" type="BaseThemeService" optional>
  Supplies the theme builder used by `getTheme(context)`. Override with a `final` field holding your custom `BaseThemeService` subclass.
</Property>

---

<Property name="loadingService" type="BaseLoadingService" optional>
  Supplies the controller and widget builder consumed by [`LoadingOverlay`](/libraries/core/features/loading_overlay). Defaults to a retained `DefaultLoadingService` instance.
</Property>

---

<Property name="getTheme(BuildContext context)" type="ThemeData">
  Convenience method that delegates to `themeService.theme(context)`. Reads the ambient brightness (`Theme.of(context).brightness`), generates a Material 3 seeded `ColorScheme` from `colorSeed`, and applies all component theme getters (`appBarTheme`, `elevatedButtonTheme`, `inputDecorationTheme`, etc.).

  Call `theme(context)` (or `getTheme(context)`) before reading getters on `BaseThemeService` that depend on `late ThemeData iTheme` or `late bool darkTheme`.
</Property>

---

## Standalone core utilities

The main `package:core_management/core_management.dart` barrel exports the service base classes (`BaseCoreService`, `BaseThemeService`, `BaseErrorHandlerService`, `BaseLoadingService`, and `BaseRouteService`). All other utilities use explicit sub-path imports:

    `package:core_management_route_go_router/...` — Protected routes, public paths, and post-sign-in deep-link restoration.
  </Card>
  <Card title="Typography Theme" icon="font" href="/libraries/core/features/typography_theme">
    `package:core_management/core_typography_theme.dart` — Instance-based Material 3 text style wrapper and primary text theme getters.
