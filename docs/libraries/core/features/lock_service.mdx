---
title: Lock Service
description: Guard duplicate in-isolate actions with synchronous acquire/release locks and expiring keys.
---

`CoreLockService` (`package:core_management/services/core_lock.dart`) provides synchronous, key-based in-memory locks with automatic expiration—ideal for preventing double-taps or concurrent triggers of the same client-side action within a single Dart isolate.

## Guard a client operation

Call `acquire(key)` synchronously before starting your async work, and always pair it with `release(key)` in a `finally` block:

```dart title="lib/services/save_guard.dart (suggested)"
import 'package:core_management/services/core_lock.dart';

final locks = CoreLockService();

Future<bool> saveOnce(Future<void> Function() save) async {
  if (!locks.acquire('save-profile')) return false;
  try {
    await save();
    return true;
  } finally {
    locks.release('save-profile');
  }
}
```

<Info>
  There are no `runLocked`, `unlock`, or `unlockAll` methods on `CoreLockService`, and concurrent callers do not automatically share a single result `Future`.
</Info>

## `CoreLockService` API reference

<Property name="CoreLockService({LockPersistence? persistence, Duration defaultLockDuration, Duration pollingInterval})" type="constructor">
  Creates a lock service instance. `defaultLockDuration` defaults to `Duration(seconds: 30)`. Passing a zero or negative `pollingInterval` throws an `ArgumentError`.
</Property>

---

<Property name="acquire(String key, {Duration? timeout, Duration? lockDuration})" type="bool">
  Attempts to acquire an in-memory lock for `key` until `DateTime.now().add(lockDuration ?? defaultLockDuration)`. Returns `true` immediately when the key is unlocked or its previous expiry has passed. (Keep `timeout` unset or `Duration.zero`—see the warning below.)
</Property>

---

<Property name="release(String key)" type="bool">
  Removes `key` from the in-memory lock map and notifies any release stream listeners. Returns `true` if the lock existed.
</Property>

---

<Property name="isLocked(String key) / getLockExpiry(String key)" type="bool / DateTime?">
  Checks whether `key` currently holds an unexpired in-memory lock (cleaning up the entry if expired), or returns its `DateTime` expiry (`null` if unlocked/expired). Note that `isLockedAsync` and `getLockExpiryAsync` mentioned in doc comments are not implemented.
</Property>

---

<Property name="cleanupExpiredLocks() / cleanupExpiredLocksAsync()" type="void / Future<void>">
  Purges all expired entries from the in-memory map (`cleanupExpiredLocksAsync` also calls `persistence?.cleanupExpiredLocks()`).
</Property>

---

<Property name="dispose()" type="void">
  Clears the static in-memory lock and release-controller maps and disposes `persistence`. Because `_locks` and `_releaseControllers` are `static` on `CoreLockService`, all instances in the same isolate share them—and calling `dispose()` on one instance clears locks for all of them.
</Property>

---

## Important implementation caveats

<Error>
  **Do not pass a positive `timeout` to `acquire()`:** When a key is already locked and `timeout > Duration.zero`, `_waitForLockSync` enters a broken synchronous path. Without a persistence watch stream, it runs a tight synchronous `while` loop that **freezes the Dart isolate** until the lock expires. With a watch stream, it schedules async listeners and immediately returns `false` without waiting. Always call `acquire('key')` without `timeout` and handle `false` gracefully.
</Error>

<AccordionGroup>
  <Accordion defaultOpen title="No owner tokens or lease renewal">
    If an async operation takes longer than `lockDuration` (default 30s), a second caller can acquire the same `key`. When the first caller eventually hits its `finally` block and calls `release(key)`, it will delete the second caller's active lock. Size `lockDuration` generously for slow network calls.
  </Accordion>
  <Accordion title="Persistence is fire-and-forget mirroring, not distributed locking">
    You can implement `LockPersistence` (`package:core_management/repositories/lock.dart`) with `createOrUpdateLock`, `getLockExpiry`, `deleteLock`, `watchLockRelease`, `cleanupExpiredLocks`, and `dispose`. However, `acquire()` and `release()` only mirror updates to `persistence` inside unawaited background microtasks (`Future.microtask`), printing errors to the console. `acquire()` never reads from `persistence` before granting a lock, so it does not coordinate across multiple isolates, processes, or servers.
  </Accordion>
</AccordionGroup>
