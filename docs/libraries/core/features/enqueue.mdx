## Add the mixin

`TaskQueueMixin<T>` applies to `State<T>`. Import its library directly.

```dart title="lib/widgets/queued_counter.dart (suggested)"
import 'package:core_management/mixins/task_queue.dart';
import 'package:flutter/material.dart';

class QueuedCounter extends StatefulWidget {
  const QueuedCounter({super.key});

  @override
  State<QueuedCounter> createState() => _QueuedCounterState();
}

class _QueuedCounterState extends State<QueuedCounter>
    with TaskQueueMixin<QueuedCounter> {
  int count = 0;

  @override
  Widget build(BuildContext context) => TextButton(
    onPressed: () => enqueue(() => setState(() => count++)),
    child: Text('$count'),
  );
}
```

## Execution contract

`enqueue(VoidCallback callback)` appends work to a FIFO queue. Before invoking each callback, the wrapper checks `mounted`.

- During scheduler `idle` or `postFrameCallbacks`, execution is immediate. It does **not** always wait for the next frame.
- During other scheduler phases, the queue registers a post-frame callback, then continues processing after that callback runs.
- `dispose()` clears queued callbacks. A scheduled callback also checks `mounted` before touching the queue.

For an operation that must run after the first frame regardless of the current phase, use Flutter's `addPostFrameCallback` explicitly instead.

## Async work and errors

The queue accepts `VoidCallback`, not an asynchronous task contract. Passing an `async` closure does not make the queue await its `Future`; FIFO invocation is not sequential completion of network requests.

The implementation does not catch callback exceptions or reset `_isProcessing` in a `finally` block. A thrown callback can interrupt processing and leave later queued work stuck. Catch expected errors inside callbacks, and handle async errors in the async operation itself.

The mounted check only protects invocation. If a callback starts asynchronous work, check `mounted` again after awaiting before using the widget's state.
