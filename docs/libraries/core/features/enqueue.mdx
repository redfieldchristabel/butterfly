---
title: Task Queue Mixin
description: Queue mounted-safe synchronous callbacks on StatefulWidget State with scheduler-aware execution.
---

`TaskQueueMixin<T>` is a lightweight mixin for `State<T>` that queues `VoidCallback` closures in FIFO order and runs them safely when the widget is mounted and Flutter's scheduler is ready.

## Quickstart example

Import `package:core_management/mixins/task_queue.dart` directly (it is not re-exported by the main `core_management.dart` barrel):

```dart title="lib/widgets/queued_counter.dart (suggested)"
import 'package:core_management/mixins/task_queue.dart';
import 'package:flutter/material.dart';

class QueuedCounter extends StatefulWidget {
  const QueuedCounter({super.key});

  @override
  State<QueuedCounter> createState() => _QueuedCounterState();
}

class _QueuedCounterState extends State<QueuedCounter>
    with TaskQueueMixin<QueuedCounter> {
  int count = 0;

  @override
  Widget build(BuildContext context) => TextButton(
    onPressed: () => enqueue(() => setState(() => count++)),
    child: Text('$count'),
  );
}
```

## How `enqueue()` schedules work

When you call `enqueue(VoidCallback callback)`, the mixin wraps your callback in a `if (mounted)` check, pushes it onto an internal `Queue<VoidCallback>`, and inspects `SchedulerBinding.instance.schedulerPhase`:

<Steps>
  <Step title="Idle or postFrameCallbacks phase → runs immediately">
    If the scheduler is currently in `SchedulerPhase.idle` or `SchedulerPhase.postFrameCallbacks`, the queue drains synchronously right away. It does **not** wait for the next frame.
  </Step>
  <Step title="Mid-frame build/layout phase → defers to post-frame">
    During `transientCallbacks`, `midFrameMicrotasks`, or `persistentCallbacks` (such as inside `build()`), the mixin registers `SchedulerBinding.instance.addPostFrameCallback` and drains the queue once the frame finishes.
  </Step>
  <Step title="Automatic cleanup on dispose()">
    When the widget is disposed, `dispose()` clears any remaining callbacks in `_taskQueue`, and pending post-frame callbacks verify `if (mounted)` before touching state.
  </Step>
</Steps>

<Info>
  Need a callback to **always** wait until after the current or next frame—even when called from an idle event handler? Call `WidgetsBinding.instance.addPostFrameCallback` directly instead of `enqueue()`.
</Info>

## Edge cases & limitations

<Warning>
  **Uncaught exceptions halt the queue:** `_processQueue()` does not wrap `task()` in a `try / finally` block before resetting `_isProcessing = false`. If a queued callback throws an uncaught exception, `_isProcessing` stays `true` and subsequent `enqueue()` calls on that `State` instance will never run. Always catch expected exceptions inside your callback.
</Warning>

<AccordionGroup>
  <Accordion defaultOpen title="Synchronous VoidCallback only (not an async task queue)">
    `enqueue` takes a synchronous `VoidCallback` (`void Function()`). Passing an `async` closure (`() async { await fetchData(); }`) invokes the closure in FIFO order, but the queue **does not `await` the returned `Future`** before starting the next queued callback.
  </Accordion>
  <Accordion title="Check mounted after awaiting inside an async callback">
    The mixin's `if (mounted)` guard runs immediately before invoking your callback. If your callback kicks off async work, check `if (!mounted) return;` again after every `await` before calling `setState`.
  </Accordion>
</AccordionGroup>
