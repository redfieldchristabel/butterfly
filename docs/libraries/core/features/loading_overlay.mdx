## Connect the overlay

`LoadingOverlay` accepts `child` and `key`. There are no `isLoading`, `opacity`, `indicator`, or `color` constructor parameters. It obtains its controller from `BaseCoreService.instance.loadingService`, so construct your core service before building it.

```dart
import 'package:core_management/core_management.dart';
import 'package:core_management/widgets/loading_overlay.dart';
import 'package:flutter/material.dart';

class AppLoadingService extends BaseLoadingService {
  @override
  Widget loadingWidget<T>(T data) => const Stack(
    fit: StackFit.expand,
    children: [
      ModalBarrier(dismissible: false, color: Color(0x66000000)),
      Center(child: CircularProgressIndicator()),
    ],
  );
}

class AppCore extends BaseCoreService {
  @override
  final BaseLoadingService loadingService = AppLoadingService();
}

void main() {
  WidgetsFlutterBinding.ensureInitialized();
  final core = AppCore();
  runApp(MaterialApp(
    builder: (context, child) => LoadingOverlay(child: child!),
    home: Scaffold(body: Center(child: ElevatedButton(
      onPressed: () async {
        final controller = core.loadingService.controller;
        controller.state = ButterflyLoadingState.loading;
        try {
          await Future<void>.delayed(const Duration(milliseconds: 300));
        } finally {
          controller.state = ButterflyLoadingState.idle;
        }
      },
      child: const Text('Load'),
    ))),
  ));
}
```

The custom service provides the centered spinner and input-blocking barrier. The default service returns only a `CupertinoActivityIndicator`; it does not itself provide a modal barrier, centered layout, or dimmed background.

## Controller API

`ButterflyLoadingController<T>` extends `ChangeNotifier`. Use its `state` and `data` properties; there are no `startLoading()` or `stopLoading()` methods.

The enum has exactly `idle`, `loading`, and `completed`. It has no `success` or `error` values. `idle` removes an existing overlay entry; entering `loading` notifies listeners so an entry can be inserted.

## Current limitations

These describe the implementation, not intended behavior:

- Assigning `completed` schedules a transition to `idle` after `kThemeAnimationDuration`. The setter does not actually assign or notify a `completed` state first. Do not use it as an observable success state.
- The `data` setter calls `notifyListeners()` but does not assign its argument to `_data`. Consequently, `data` remains null; passing messages through it does not work.
- A completion timer is not canceled when assigning another ordinary state. A pending completion can therefore hide a later loading operation.
- The overlay subscribes during `initState` but does not immediately reconcile the controller's existing state. Set loading after the overlay mounts, not before.
- There is no request counter or per-operation ownership. Concurrent operations can hide one another's loading state.

The example uses `loading` and `idle` with `try/finally`, does not depend on `data`, and supplies its own modal visuals. It does not fix the underlying implementation.

Implementation: `packages/core_management/lib/widgets/loading_overlay.dart`, `lib/services/base_loading.dart`, and `lib/src/services/default_loading.dart`.
