---
title: Riverpod Auto-Sync
description: Publish the signed-in user to Riverpod automatically with one initialize(ref) call and a typed userProvider.
---

`auth_management_provider_riverpod` connects your `AuthService` to Riverpod with **zero manual publish/clear boilerplate**. Once wired, signing in, restoring a cached session, or calling `signOut()` updates your widgets automatically.

## Setup: Butterfly vs. Raw Riverpod

<Info>Only `lib/main.dart` is a fixed name. Files marked **(suggested)** follow the `butterfly init` layout; rename or move them freely. Replace `my_app` in imports with the `name` from your `pubspec.yaml`.</Info>

<Tabs>
  <TabItem label="With Butterfly" value="with-butterfly">
    Install Riverpod codegen, mix `RiverpodUser` into `AppUser` with a 1-line `@riverpod` `user` proxy, return a top-level `riverpodProvider` from `providerRepo`, and call `riverpodProvider.initialize(ref)` once in your root `ConsumerWidget`:

    ```bash
    flutter pub add flutter_riverpod riverpod_annotation
    flutter pub add dev:riverpod_generator dev:build_runner
    dart run build_runner build
    ```

    ```dart title="lib/models/app_user.dart (suggested)"
    import 'package:auth_management_provider_riverpod/auth_management_provider_riverpod.dart';
    import 'package:riverpod_annotation/riverpod_annotation.dart';

    part 'app_user.g.dart';

    class AppUser with RiverpodUser {
      AppUser(this.name);
      final String name;
    }

    /// The signed-in [AppUser], or null when signed out.
    ///
    /// Generates `userProvider`. Watch it instead of `riverpodUserStateProvider`,
    /// so the cast to [AppUser] lives here once.
    @riverpod
    AppUser? user(Ref ref) => ref.watch(riverpodUserStateProvider) as AppUser?;
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'package:auth_management/auth_management.dart';
    import 'package:auth_management/auth_management_provider.dart';
    import 'package:auth_management_provider_riverpod/auth_management_provider_riverpod.dart';
    import 'package:my_app/models/app_user.dart';

    final riverpodProvider = AuthManagementRiverpodRepository<AppUser>();

    class AuthService extends AuthServiceRepository<AppUser> {
      // Use any user storage you prefer here: Sembast, Hive CE, Isar, or your
      // own AuthManagementDatabaseRepository. In-memory keeps this example
      // simple, but it forgets the user when the app restarts.
      @override
      final dbRepo = InMemoryDatabaseRepository<AppUser>();

      @override
      AuthServiceProviderRepository<AppUser> get providerRepo => riverpodProvider;
    }

    final authService = AuthService();
    ```

    ```dart title="lib/main.dart"
    import 'package:flutter/material.dart';
    import 'package:flutter_riverpod/flutter_riverpod.dart';
    import 'package:my_app/services/auth.dart';
    import 'package:my_app/widgets/user_label.dart';

    void main() {
      authService.initialize();
      runApp(const ProviderScope(child: App()));
    }

    class App extends ConsumerWidget {
      const App({super.key});

      @override
      Widget build(BuildContext context, WidgetRef ref) {
        riverpodProvider.initialize(ref);
        return const MaterialApp(home: UserLabel());
      }
    }
    ```

    ```dart title="lib/widgets/user_label.dart (suggested)"
    import 'package:flutter/material.dart';
    import 'package:flutter_riverpod/flutter_riverpod.dart';
    import 'package:my_app/models/app_user.dart';

    class UserLabel extends ConsumerWidget {
      const UserLabel({super.key});

      @override
      Widget build(BuildContext context, WidgetRef ref) {
        final user = ref.watch(userProvider);
        return Text(user?.name ?? 'Signed out');
      }
    }
    ```
  </TabItem>
  <TabItem label="Without Butterfly (Raw Riverpod)" value="without-butterfly">
    If you drop `auth_management_provider_riverpod`, you write your own `Notifier<AppUser?>` and `NotifierProvider`, and manually call `ref.read(userProvider.notifier).setUser(...)` or listen to your auth stream in a stateful root widget:

    ```dart title="lib/models/app_user.dart (suggested)"
    import 'package:flutter_riverpod/flutter_riverpod.dart';

    class AppUser {
      AppUser(this.name);
      final String name;
    }

    class UserNotifier extends Notifier<AppUser?> {
      @override
      AppUser? build() => null;

      void setUser(AppUser? user) => state = user;
    }

    final userProvider = NotifierProvider<UserNotifier, AppUser?>(
      UserNotifier.new,
    );
    ```

    ```dart title="lib/main.dart"
    import 'package:flutter/material.dart';
    import 'package:flutter_riverpod/flutter_riverpod.dart';
    import 'package:my_app/widgets/user_label.dart';

    void main() {
      runApp(const ProviderScope(child: MaterialApp(home: UserLabel())));
    }
    ```


<Warning>
  **Keep `riverpodProvider` as a single top-level instance:** Your `providerRepo` getter must return the exact same `riverpodProvider` instance on every access. Writing `get providerRepo => AuthManagementRiverpodRepository<AppUser>()` would construct a fresh, uninitialized instance every time the auth stream emits.
</Warning>

## How automatic sync works under the hood

<AccordionGroup>
  <Accordion defaultOpen title="Startup order & build-safe microtask delivery">
    You can call `authService.initialize()` in `main()` before `runApp` without worrying about race conditions:
    - Any user emitted by `streamUser()` **before** `riverpodProvider.initialize(ref)` runs is held as pending inside `AuthServiceProviderRepository`.
    - When `riverpodProvider.initialize(ref)` runs inside your root `ConsumerWidget.build`, it schedules pending delivery via `Future.microtask` so Riverpod never throws a *"tried to modify a provider while the widget tree was building"* assertion.
    - Subsequent calls to `riverpodProvider.initialize(ref)` on rebuilds are safe no-ops.
  </Accordion>
  <Accordion title="Why define userProvider instead of watching riverpodUserStateProvider directly?">
    Because Dart code generation inside `auth_management_provider_riverpod` cannot be generic over your app's `AppUser` class, the package's built-in `riverpodUserStateProvider` is a keep-alive notifier typed as `RiverpodUser?`. Adding the 2-line `@riverpod AppUser? user(Ref ref)` function in `lib/models/app_user.dart` centralizes the `as AppUser?` cast once and gives the rest of your app a clean, strongly typed `userProvider`.
  </Accordion>
  <Accordion title="Writing an adapter for another state manager (BLoC, Signals, MobX)">
    Every state manager can plug into `providerRepo` the exact same way:
    1. Extend `AuthServiceProviderRepository<T>` from `package:auth_management/auth_management_provider.dart`.
    2. Implement `@protected bindUserToProvider(T user)`, `@protected clearUser()`, and `getUser()`.
    3. Call `@protected markInitialized()` once your adapter receives its store/bloc handle—`AuthServiceProviderRepository` will immediately flush any pending user state and keep future stream events and `signOut()` calls in sync.
  </Accordion>
</AccordionGroup>
