---
title: Firebase, Google & OAuth2 Providers
description: Connect Firebase Auth, Google Sign-In, or an OAuth2 server to your domain AppUser model.
---

Butterfly's identity provider packages observe external authentication sessions (Firebase Auth or OAuth2) and resolve your own `AppUser` model through `fetchUser`.

## Choose an identity provider

<Tabs>
  <TabItem label="Firebase Auth" value="firebase-tab">
    `FirebaseAuthManagementRepository<T extends FirebaseUser>` (`package:auth_management_firebase/auth_management_firebase.dart`) listens to `FirebaseAuth.instance.authStateChanges()` and maps `firebase.User` to your `AppUser` model.

    <Info>Only `lib/main.dart` is a fixed name. Files marked **(suggested)** follow the `butterfly init` layout; rename or move them freely. Replace `my_app` in imports with the `name` from your `pubspec.yaml`.</Info>

    <Steps>
      <Step title="Mix FirebaseUser into your AppUser model">
        Return the Firebase account's UID from `firebaseUid` so the repository can verify whether a cached `AppUser` belongs to the active Firebase session:

        ```dart title="lib/models/app_user.dart (suggested)"
        import 'package:auth_management_firebase/auth_management_firebase.dart';

        class AppUser with FirebaseUser {
          AppUser({required this.uid, required this.role});
          final String uid;
          final String role;

          @override
          String get firebaseUid => uid;
        }
        ```
      </Step>
      <Step title="Extend FirebaseAuthManagementRepository<AppUser>">
        Implement `dbRepo` and `fetchUser(firebase.User identity)` to load your app profile from Firestore or your backend API:

        ```dart title="lib/services/auth.dart (suggested)"
        import 'package:auth_management/auth_management.dart';
        import 'package:auth_management_firebase/auth_management_firebase.dart';
        import 'package:firebase_auth/firebase_auth.dart' as firebase;
        import 'package:my_app/models/app_user.dart';

        class AuthService extends FirebaseAuthManagementRepository<AppUser> {
          AuthService({required this.dbRepo, required this.loadProfile});

          @override
          final AuthManagementDatabaseRepository<AppUser> dbRepo;
          final Future<AppUser> Function(String uid) loadProfile;

          @override
          Future<AppUser> fetchUser(firebase.User identity) => loadProfile(identity.uid);
        }
        ```
      </Step>
    </Steps>

    - **Sign-in helper:** Call `await authService.signInWithEmailAndPassword(email, password)` (positional strings). It returns Firebase's `UserCredential` while `authStateChanges()` triggers `fetchUser` and updates `streamUser()` / `currentUser` / `providerRepo`.
    - **Cache matching:** `isCachedUserFor` compares `cachedUser.firebaseUid == identity.uid`. Call `await authService.refreshUser()` whenever you want to bypass the cache and re-run `fetchUser`.
  </TabItem>
  <TabItem label="Google Sign-In Mixins" value="google-tab">
    Two mixins add Google Sign-In on top of `FirebaseAuthManagementRepository`:

    | Target Platform | Import Path | Mixin & Methods |
    | --- | --- | --- |
    | **Native (Android / iOS)** | `package:auth_management_firebase_google/auth_management_firebase_google.dart` | `SignInWithGoogleFirebase` → `signInWithGoogle()` |
    | **Web (Popup / Redirect)** | `package:auth_management_firebase/auth_management_firebase_google.dart` | `SignInWithGoogleWebMixin` → `signInWithGoogle()`, `signInWithGoogleRedirect()` |

    <Error>
      **Generic constraint bug on `SignInWithGoogleFirebase`:** The native mixin declares a raw `on FirebaseAuthManagementRepository` constraint (without `<T extends FirebaseUser>`). Mixing it onto `class AuthService extends FirebaseAuthManagementRepository<AppUser>` causes a Dart analyzer error (`can't implement both AuthServiceRepository<AppUser> and AuthServiceRepository<FirebaseUser>`). Parameterize the mixin as `mixin SignInWithGoogleFirebase<T extends FirebaseUser> on FirebaseAuthManagementRepository<T>` in the package source before applying it to a typed `AppUser` subclass.
    </Error>

    <Warning>
      **Override `scopes` and `customParameters` on `SignInWithGoogleWebMixin`:** The web mixin's built-in defaults request the `contacts.readonly` scope and set `'login_hint': 'user@example.com'`. Always override both getters in your `AuthService` with your real scopes and parameters.
    </Warning>
  </TabItem>
  <TabItem label="OAuth2" value="oauth2-tab">
    `BaseOauth2AuthManagement<T>` (`package:auth_management_oauth2/auth_management_oauth2.dart`) manages an `oauth2.Client` session and resolves your `AppUser` via `fetchUser(oauth2.Client session)`:

    ```dart title="lib/models/app_user.dart (suggested)"
    class AppUser {
      AppUser(this.id);
      final String id;
    }
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'dart:convert';

    import 'package:auth_management_oauth2/auth_management_oauth2.dart';
    import 'package:my_app/models/app_user.dart';
    import 'package:oauth2/oauth2.dart' as oauth2;

    // Profile-resolution skeleton only: supply configuration, dbRepo, and sign-in.
    abstract class AuthService extends BaseOauth2AuthManagement<AppUser> {
      Uri get profileEndpoint;

      @override
      Future<AppUser> fetchUser(oauth2.Client session) async {
        final response = await session.get(profileEndpoint);
        if (response.statusCode != 200) {
          throw StateError('Profile request failed: ${response.statusCode}');
        }
        final json = jsonDecode(response.body) as Map<String, dynamic>;
        return AppUser(json['id'] as String);
      }
    }
    ```

    ### OAuth2 grant mixins

    | Sub-import under `package:auth_management_oauth2/` | Mixin | Method & Required Getters |
    | --- | --- | --- |
    | `mixins/authorization_code_grant.dart` | `AuthorizationCodeGrantMixin` | `signInWithAuthorizationCode()` — requires `tokenEndpoint` & `redirectUrl` |
    | `mixins/client_credential.dart` | `ClientCredential` | `signInWithClientCredential()` — uses `authorizationEndpoint` |
    | `mixins/resource_owner_password_grant.dart` | `ResourceOwnerPasswordGrant` | `signInWithPassword(username: ..., password: ...)` |

    <Error>
      **Generic constraint bug on all three OAuth2 grant mixins:** Like the native Google mixin, `AuthorizationCodeGrantMixin`, `ClientCredential`, and `ResourceOwnerPasswordGrant` declare raw `on BaseOauth2AuthManagement` constraints, causing a conflicting generic interface error when mixed into `BaseOauth2AuthManagement<AppUser>`. Add `<T> on BaseOauth2AuthManagement<T>` to the mixin declarations before combining them with a typed `AppUser`.
    </Error>
  </TabItem>
</Tabs>

## OAuth2 session & security checklist

<AccordionGroup>
  <Accordion defaultOpen title="Plaintext credentials.json & platform support">
    `BaseOauth2AuthManagement` persists OAuth2 credentials as plaintext JSON in `<appDocumentsDir>/credentials.json` using `dart:io`. It does **not** use encrypted keychain/keystore storage and does **not** work on Flutter Web. Furthermore, never ship a confidential OAuth2 `secret` inside a mobile or desktop client binary.
  </Accordion>
  <Accordion title="Await initialize() & watch out for unawaited storeClient()">
    - Call `await authService.initialize()` at startup so any existing `credentials.json` is restored before listening to `streamUser()`.
    - The grant mixins call `storeClient(...)` without `await`, so a completed sign-in future does not guarantee `credentials.json` has finished flushing to disk.
    - Unlike Firebase, `BaseOauth2AuthManagement` inherits the base `isCachedUserFor` (`true`). Override `isCachedUserFor` or clear `dbRepo` before switching accounts so a previous user's cached profile is never reused.
  </Accordion>
</AccordionGroup>
