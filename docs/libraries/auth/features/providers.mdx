Butterfly's identity provider packages observe external authentication sessions (Firebase Auth or OAuth2) and resolve your own `AppUser` model through `fetchUser`.

## Firebase Auth: Butterfly vs. Raw `firebase_auth`

<Info>Only `lib/main.dart` is a fixed name. Files marked **(suggested)** follow the `butterfly init` layout; rename or move them freely. Replace `my_app` in imports with the `name` from your `pubspec.yaml`.</Info>

<Tabs>
  <TabItem label="With Butterfly" value="firebase-with-butterfly">
    Mix `FirebaseUser` into `AppUser` and extend `FirebaseAuthManagementRepository<AppUser>`. Butterfly watches `authStateChanges()`, checks if `dbRepo` already holds a matching UID (`cachedUser.firebaseUid == identity.uid`), deduplicates concurrent `fetchUser` calls, and updates `streamUser()` and `providerRepo`:

    ```dart title="lib/models/app_user.dart (suggested)"
    import 'package:auth_management_firebase/auth_management_firebase.dart';

    class AppUser with FirebaseUser {
      AppUser({required this.uid, required this.role});
      final String uid;
      final String role;

      @override
      String get firebaseUid => uid;
    }
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'package:auth_management/auth_management.dart';
    import 'package:auth_management_firebase/auth_management_firebase.dart';
    import 'package:firebase_auth/firebase_auth.dart' as firebase;
    import 'package:my_app/models/app_user.dart';

    class AuthService extends FirebaseAuthManagementRepository<AppUser> {
      AuthService({required this.dbRepo, required this.loadProfile});

      @override
      final AuthManagementDatabaseRepository<AppUser> dbRepo;
      final Future<AppUser> Function(String uid) loadProfile;

      @override
      Future<AppUser> fetchUser(firebase.User identity) => loadProfile(identity.uid);
    }
    ```
  </TabItem>
  <TabItem label="Without Butterfly (Raw firebase_auth)" value="firebase-without-butterfly">
    Without `auth_management_firebase`, you subscribe to `FirebaseAuth.instance.authStateChanges().asyncMap(...)` yourself and wire UID cache checks and `signOut` manually:

    ```dart title="lib/models/app_user.dart (suggested)"
    class AppUser {
      AppUser({required this.uid, required this.role});
      final String uid;
      final String role;
    }
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'package:firebase_auth/firebase_auth.dart' as firebase;
    import 'package:my_app/models/app_user.dart';

    class RawFirebaseAuthService {
      RawFirebaseAuthService({required this.loadProfile});

      final Future<AppUser> Function(String uid) loadProfile;
      final firebase.FirebaseAuth _firebaseAuth = firebase.FirebaseAuth.instance;
      AppUser? _cachedUser;

      Stream<AppUser?> streamUser() =>
          _firebaseAuth.authStateChanges().asyncMap((identity) async {
            if (identity == null) {
              _cachedUser = null;
              return null;
            }
            if (_cachedUser != null && _cachedUser!.uid == identity.uid) {
              return _cachedUser;
            }
            final user = await loadProfile(identity.uid);
            _cachedUser = user;
            return user;
          });

      Future<firebase.UserCredential> signInWithEmailAndPassword(
        String email,
        String password,
      ) => _firebaseAuth.signInWithEmailAndPassword(
        email: email,
        password: password,
      );

      Future<void> signOut() async {
        await _firebaseAuth.signOut();
        _cachedUser = null;
      }
    }
    ```
  </TabItem>
</Tabs>

## OAuth2: Butterfly vs. Raw `oauth2`

<Tabs>
  <TabItem label="With Butterfly" value="oauth2-with-butterfly">
    Extend `BaseOauth2AuthManagement<AppUser>` and implement `fetchUser(oauth2.Client session)` to resolve your domain model from an authenticated OAuth2 session:

    ```dart title="lib/models/app_user.dart (suggested)"
    class AppUser {
      AppUser(this.id);
      final String id;
    }
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'dart:convert';

    import 'package:auth_management_oauth2/auth_management_oauth2.dart';
    import 'package:my_app/models/app_user.dart';
    import 'package:oauth2/oauth2.dart' as oauth2;

    // Profile-resolution skeleton only: supply configuration, dbRepo, and sign-in.
    abstract class AuthService extends BaseOauth2AuthManagement<AppUser> {
      Uri get profileEndpoint;

      @override
      Future<AppUser> fetchUser(oauth2.Client session) async {
        final response = await session.get(profileEndpoint);
        if (response.statusCode != 200) {
          throw StateError('Profile request failed: ${response.statusCode}');
        }
        final json = jsonDecode(response.body) as Map<String, dynamic>;
        return AppUser(json['id'] as String);
      }
    }
    ```
  </TabItem>
  <TabItem label="Without Butterfly (Raw oauth2)" value="oauth2-without-butterfly">
    Without `auth_management_oauth2`, you manage the `oauth2.Client` directly and call your profile endpoint using `session.get(...)`:

    ```dart title="lib/models/app_user.dart (suggested)"
    class AppUser {
      AppUser(this.id);
      final String id;
    }
    ```

    ```dart title="lib/services/auth.dart (suggested)"
    import 'dart:convert';

    import 'package:my_app/models/app_user.dart';
    import 'package:oauth2/oauth2.dart' as oauth2;

    class RawOauth2Service {
      RawOauth2Service({required this.profileEndpoint});

      final Uri profileEndpoint;

      Future<AppUser> fetchUser(oauth2.Client session) async {
        final response = await session.get(profileEndpoint);
        if (response.statusCode != 200) {
          throw StateError('Profile request failed: ${response.statusCode}');
        }
        final json = jsonDecode(response.body) as Map<String, dynamic>;
        return AppUser(json['id'] as String);
      }
    }
    ```
  </TabItem>
</Tabs>

## Google Sign-In & OAuth2 grant mixins

| Integration | Import Path | Mixin & Methods |
| --- | --- | --- |
| **Google Native (Android / iOS)** | `package:auth_management_firebase_google/auth_management_firebase_google.dart` | `SignInWithGoogleFirebase` → `signInWithGoogle()` |
| **Google Web (Popup / Redirect)** | `package:auth_management_firebase/auth_management_firebase_google.dart` | `SignInWithGoogleWebMixin` → `signInWithGoogle()`, `signInWithGoogleRedirect()` |
| **OAuth2 Auth Code Grant** | `package:auth_management_oauth2/mixins/authorization_code_grant.dart` | `AuthorizationCodeGrantMixin` → `signInWithAuthorizationCode()` |
| **OAuth2 Client Credentials** | `package:auth_management_oauth2/mixins/client_credential.dart` | `ClientCredential` → `signInWithClientCredential()` |
| **OAuth2 Password Grant** | `package:auth_management_oauth2/mixins/resource_owner_password_grant.dart` | `ResourceOwnerPasswordGrant` → `signInWithPassword(...)` |

<Error>
  **Generic constraint bug on `SignInWithGoogleFirebase` and the three OAuth2 grant mixins:** These four mixins declare raw `on FirebaseAuthManagementRepository` / `on BaseOauth2AuthManagement` constraints without a `<T>` type parameter. Applying them directly to a typed `AppUser` subclass triggers a Dart analyzer error (`can't implement both AuthServiceRepository<AppUser> and AuthServiceRepository<...>`). Parameterize the mixin declarations with `<T>` in the package source before combining them with a typed `AppUser`.
</Error>

<Warning>
  **Override `scopes` and `customParameters` on `SignInWithGoogleWebMixin`:** The web mixin's built-in defaults request the `contacts.readonly` scope and set `'login_hint': 'user@example.com'`. Always override both getters in your `AuthService` with your real scopes and parameters.
</Warning>

## OAuth2 session & security checklist

<AccordionGroup>
  <Accordion defaultOpen title="Plaintext credentials.json & platform support">
    `BaseOauth2AuthManagement` persists OAuth2 credentials as plaintext JSON in `<appDocumentsDir>/credentials.json` using `dart:io`. It does **not** use encrypted keychain/keystore storage and does **not** work on Flutter Web. Furthermore, never ship a confidential OAuth2 `secret` inside a mobile or desktop client binary.
  </Accordion>
  <Accordion title="Await initialize() & watch out for unawaited storeClient()">
    - Call `await authService.initialize()` at startup so any existing `credentials.json` is restored before listening to `streamUser()`.
    - The grant mixins call `storeClient(...)` without `await`, so a completed sign-in future does not guarantee `credentials.json` has finished flushing to disk.
    - Unlike Firebase, `BaseOauth2AuthManagement` inherits the base `isCachedUserFor` (`true`). Override `isCachedUserFor` or clear `dbRepo` before switching accounts so a previous user's cached profile is never reused.
  </Accordion>
</AccordionGroup>
