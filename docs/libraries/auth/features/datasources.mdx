---
title: User Storage Repositories
description: Persist your signed-in AppUser locally with Sembast, Hive CE, Isar Community, or a custom AuthManagementDatabaseRepository.
---

Every `AuthServiceRepository<T>` requires a `dbRepo` implementing `AuthManagementDatabaseRepository<T>` (`package:auth_management/auth_management.dart`). This repository caches your resolved `AppUser` locally—it does **not** perform password verification or network sign-in.

## Compare storage adapters

| Package | Repository Class | Model Requirement | Current Status |
| --- | --- | --- | --- |
| `auth_management_database_sembast` | `AuthManagementDatabaseSembast<T>` | `fromJson` & `toJson` callbacks | **Recommended** — awaits writes, emits initial snapshot on `streamUser()` |
| `auth_management_database_hive_ce` | `AuthManagementDatabaseHiveCe<T>` | Extend Hive `BaseUser` + register type adapter | Works with caveats — `addUser`/`clearUser` do not `await` box futures |
| `auth_management_database_isar_community` | `AuthManagementIsarRepository<T>` | Extend Isar `BaseUser` + supply `CollectionSchema<T>` | **Needs code fixes** — unawaited `getUser()` cast & missing transaction in `clearUser()` |
| `auth_management` | `InMemoryDatabaseRepository<T>` | None | Testing/prototyping only — non-persistent, no initial stream emission |

## Adapter setup guides

<Tabs>
  <TabItem label="Sembast (Recommended)" value="sembast">
    `AuthManagementDatabaseSembast<T>` attaches to an already-open Sembast `Database` instance that your app owns. It needs no base model inheritance or Hive/Isar binary adapter generation.

    <Info>Only `lib/main.dart` is a fixed name. Files marked **(suggested)** follow the `butterfly init` layout; rename or move them freely. Replace `my_app` in imports with the `name` from your `pubspec.yaml`.</Info>

    ```dart title="lib/models/app_user.dart (suggested)"
    class AppUser {
      const AppUser(this.id);
      final String id;

      factory AppUser.fromJson(Map<String, Object?> json) =>
          AppUser(json['id'] as String);

      Map<String, Object?> toJson() => {'id': id};
    }
    ```

    ```dart title="lib/services/user_cache.dart (suggested)"
    import 'package:auth_management_database_sembast/auth_management_database_sembast.dart';
    import 'package:my_app/models/app_user.dart';
    import 'package:sembast/sembast.dart';

    AuthManagementDatabaseSembast<AppUser> createUserCache(Database database) {
      return AuthManagementDatabaseSembast<AppUser>(
        fromJson: AppUser.fromJson,
        toJson: (user) => user.toJson(),
      )..initialize(database);
    }
    ```

    - **Store & key:** Stores the single active user at key `'current'` inside store `'auth_management_user'` (customizable via constructor `storeName`).
    - **Lifecycle:** Call `initialize(database)` before any read/write (otherwise a `StateError` is thrown). `streamUser()` emits the initial cached user (or `null`) immediately upon subscription, and `addUser` / `clearUser` properly `await` their Sembast transactions.
  </TabItem>
  <TabItem label="Hive CE" value="hive-ce">
    1. Import `AuthManagementDatabaseHiveCe<T>` from `package:auth_management_database_hive_ce/auth_management_database_hive_ce.dart` and `BaseUser` from `package:auth_management_database_hive_ce/base_user.dart`.
    2. Subclass `BaseUser` (which extends `HiveObject`) and register your generated Hive `TypeAdapter` **before** calling `await hiveRepo.initialize()`.
    3. `initialize()` resolves `getApplicationDocumentsDirectory()`, initializes Hive there, and opens box `'currentUser'`, storing the active record at integer key `0`.

    <Warning>
      **Unawaited writes & native-only path:** `AuthManagementDatabaseHiveCe.addUser` calls `_userBox.put(0, user)` and `clearUser` calls `_userBox.clear()` without returning or awaiting the `Future`. In addition, `initialize()` calls `getApplicationDocumentsDirectory()` unconditionally, which is not supported on Flutter Web.
    </Warning>
  </TabItem>
  <TabItem label="Isar Community" value="isar">
    `AuthManagementIsarRepository<T>` requires your model to extend `BaseUser` from `package:auth_management_database_isar_community/auth_management_database_isar_community.dart` (which provides `Id id = Isar.autoIncrement`) and requires calling `await isarRepo.initialize(AppUserSchema)` before use. It throws `UnsupportedError` on Web.

    <Error>
      **Current implementation defects in `AuthManagementIsarRepository`:**
      - **`getUser()` broken cast:** Calls `_userCollection.where().findFirst()` (which returns a `Future<T?>`) and casts it directly `as T?` without `await` or `.findFirstSync()`.
      - **`clearUser()` missing writeTxn:** Calls `_userCollection.clear()` outside `_isar.writeTxn(...)` and without awaiting the returned `Future`.
      - **`streamUser()` no initial emission:** Calls `.watch()` without `fireImmediately: true`, so listeners do not receive the cached user at startup until a write occurs.

      Fix these three methods in `packages/auth_management_database_isar_community/lib/src/repository.dart` before using Isar in production.
    </Error>
  </TabItem>
  <TabItem label="In-Memory" value="in-memory">
    `InMemoryDatabaseRepository<T>` (`package:auth_management/auth_management.dart`) wraps a `ValueNotifier<T?>(null)`.
    - **Best for:** Unit tests, widget previews, and quick Riverpod prototypes.
    - **Limitations:** Loses state on app restart, does not emit the current value when `streamUser()` is first subscribed to, and does not remove its listener on stream cancellation.
  </TabItem>
</Tabs>

## Implementing a custom storage adapter

To plug in SQLite (`drift` / `sqflite`), `shared_preferences`, or `flutter_secure_storage`, implement the four-method `AuthManagementDatabaseRepository<T>` interface:

<Property name="getUser()" type="FutureOr<T?>">
  Returns the currently cached user, or `null` if none is stored.
</Property>

---

<Property name="addUser(T user)" type="FutureOr<void>">
  Persists `user` as the active user and notifies `streamUser()` listeners.
</Property>

---

<Property name="clearUser()" type="FutureOr<void>">
  Deletes the stored user record and emits `null` on `streamUser()`.
</Property>

---

<Property name="streamUser()" type="Stream<T?>">
  Emits the initial cached user (or `null`) on subscription, followed by every subsequent `addUser` or `clearUser` update.
</Property>
