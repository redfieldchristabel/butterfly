## The contract

The exported interface is `AuthManagementDatabaseRepository<T>`, not `AuthDataSource`. It stores your application user; it does not authenticate passwords.

| Method | Return type |
| --- | --- |
| `getUser()` | `FutureOr<T?>` |
| `addUser(T user)` | `FutureOr<void>` |
| `clearUser()` | `FutureOr<void>` |
| `streamUser()` | `Stream<T?>` |

Implement this interface for another backend and return it from your auth service's `dbRepo` getter. For predictable startup, a custom stream should emit the current cached value when subscribed, then later changes. Adapters differ in whether they currently satisfy that behavior.

## Adapter map

| Package | Concrete repository | Model requirement |
| --- | --- | --- |
| `auth_management` | `InMemoryDatabaseRepository<T>` | None |
| `auth_management_database_sembast` | `AuthManagementDatabaseSembast<T>` | `fromJson` and `toJson` callbacks |
| `auth_management_database_hive_ce` | `AuthManagementDatabaseHiveCe<T>` | Extend that package's `BaseUser`; register a Hive adapter |
| `auth_management_database_isar_community` | `AuthManagementIsarRepository<T>` | Extend that package's `BaseUser`; provide a collection schema |

Firebase is an identity-provider integration, not an implementation of this cache contract. There is no `FirebaseAuthDataSource`, `HiveAuthDataSource`, or `IsarAuthDataSource` in these packages.

## Sembast

The repository uses your already-open database. It neither opens nor closes that database and needs no generated adapter or base model class.

```dart
import 'package:auth_management_database_sembast/auth_management_database_sembast.dart';
import 'package:sembast/sembast.dart';

class AppUser {
  const AppUser(this.id);
  final String id;

  factory AppUser.fromJson(Map<String, Object?> json) =>
      AppUser(json['id'] as String);

  Map<String, Object?> toJson() => {'id': id};
}

AuthManagementDatabaseSembast<AppUser> createUserCache(Database database) {
  return AuthManagementDatabaseSembast<AppUser>(
    fromJson: AppUser.fromJson,
    toJson: (user) => user.toJson(),
  )..initialize(database);
}
```

The default store is `auth_management_user` and the single record key is `current`. Set constructor `storeName` only when a different store is needed. Calling a storage operation before `initialize(database)` throws `StateError`.

`streamUser()` maps record snapshots, including the initial record or null. `addUser` and `clearUser` await their database operations. Convert nested models to maps and dates to supported Sembast values; for generated JSON, configure nested serialization appropriately.

## Hive CE

Import the repository from `auth_management_database_hive_ce.dart`. Its `BaseUser` requires a separate import from `package:auth_management_database_hive_ce/base_user.dart` and extends `HiveObject`.

Register the user type adapter before calling `initialize()`. Initialization uses `getApplicationDocumentsDirectory()` and opens a typed box named `currentUser`. The current user is stored at integer key `0`. `streamUser()` emits the existing value and then watches that key, canceling its box subscription when the consumer cancels.

The adapter's `addUser` and `clearUser` invoke asynchronous Hive operations without returning or awaiting their futures. Awaiting these wrapper methods does not guarantee disk persistence has completed. The implementation relies on a filesystem documents directory; do not infer browser compatibility solely from Hive's capabilities.

## Isar Community

Call `initialize(userSchema, schemas: additionalSchemas)` before use. Initialization opens an Isar instance in the application documents directory and explicitly throws on web. This package exports its own `BaseUser`, containing a required `Id id`; it is different from Hive's `BaseUser`.

Current implementation limitations are important:

- `addUser` writes the model in a synchronous write transaction. It does not replace all other user records.
- `getUser` calls asynchronous `findFirst()` and casts that result directly to `T?`, rather than awaiting it. It is not a working typed read as written.
- `clearUser` calls `collection.clear()` without an explicit write transaction and without awaiting/returning its future.
- The query stream does not request an initial emission (`fireImmediately`); it selects the first returned user after changes.

Review or repair these behaviors before selecting this adapter for production. These docs do not claim that a placeholder package test verifies actual native database operations.

## In-memory storage

`InMemoryDatabaseRepository<T>` holds a `ValueNotifier<T?>`. It loses data on restart. Its stream attaches a notifier listener but does not emit the existing value immediately or unregister that listener on cancellation. It is suitable for limited development scenarios, not a persistent-session solution or a leak-free lifecycle abstraction.

Implementation: each adapter's `lib/repository.dart` or `lib/src/repository.dart`, plus `packages/auth_management/lib/src/in_memory_database_repo.dart`.
